Step 01

Roles belong in code, spelled the way they are stored

Every user has exactly one role (plan §3), and every permission check will start from it. Roles live in code rather than in a table, so adding one is a reviewed change, not a row someone inserts by hand (plan §6, ADR-0003).

Each role's value is what the database stores and what the API returns, so it is part of your data format. Renaming "Receptionist" to "receptionist" once rows exist needs a data migration; spelling it right now costs nothing.

What your code has to do
  1. Define all eight roles from plan §3 now, including the Phase 4 and 5 ones, so the column and its CHECK constraint already accept them.
  2. Make each member a string as well as an enum member, so it serializes to JSON as plain text and compares equal to that text.
  3. Use lowercase snake_case values for every member, without exception: the values are what the database stores.
  4. Put it in app/core/permissions.py, where Permission joins it later in this milestone.
  5. Prove it imports: uv run python -c "from app.core.permissions import Role; print(list(Role))".
Hint — the imports this step needs
StrEnum
An enum whose members are also strings. Role.ADMIN == "admin" is true, and the member serializes as "admin". It already subclasses str, which is why listing str as well breaks it.

Step 02

An enum column the database can check

Plan §7 stores enums as strings rather than PostgreSQL enum types, because changing a native enum needs awkward migrations. A plain VARCHAR accepts any text, though, so the column needs a CHECK constraint listing the allowed values. With it, the database rejects a bad role even from raw SQL.

SQLAlchemy's Enum type can do all of that, but two of its defaults are wrong here: it stores the member's name ("ADMIN") rather than its value, and it creates no CHECK unless asked. Appointments, prescriptions and tickets will need the same kind of column, so the settings go in one helper.

What your code has to do
  1. Store each member's value, not its name, so the database, the API and SQL filters all use "admin".
  2. Create a named CHECK constraint. The naming convention in app/db/base.py builds ck_<table>_<name> from it, so the name has to be passed in.
  3. Reject an unknown string in Python, before any SQL is sent, so a typo fails with a clear error.
  4. Fix the column length instead of letting it follow the longest current value, so adding a member later changes only the CHECK.
  5. Return the type, so a model can write mapped_column(string_enum(Role, name="role")).
Hint — the imports this step needs
Enum (from sqlalchemy)
SQLAlchemy's column type for Python enums. Not the Enum from Python's enum module: with that one, Enum(Role, name=...) raises TypeError: ... unexpected keyword argument 'name'.
native_enum=False
Stores the value as VARCHAR. Without it, PostgreSQL gets a native ENUM type, which plan §7 avoids.
create_constraint
Set to True, adds the CHECK constraint, which is off by default. A misspelled keyword is accepted without an error and does nothing, so confirm the constraint in the generated DDL.
values_callable
Tells SQLAlchemy which strings to store. Returning each member's .value stores "admin" instead of "ADMIN".
validate_strings
Set to True, checks plain strings in Python. "superuser" raises LookupError before the query runs.
backend/app/modules/users/models.py 
def string_enum(enum_cls: type[StrEnum], *, name: str, length: int = 32) -> Enum:
    """Build a column type that stores a ``StrEnum`` as a checked VARCHAR.

    Returns:
        A SQLAlchemy ``Enum`` type to pass to ``mapped_column``.
    """
    return Enum(
        enum_cls,
        name=name,
        native_enum=False,
        length=length,
        create_constraint=True,
        validate_strings=True,
        values_callable=lambda members: [member.value for member in members],
    )

Step 03

The users table, with rules any writer must obey

Some rules must hold whoever writes the row: the service, a seed script, a migration, or someone at a SQL prompt. Those belong in the database: a unique constraint on the email, a CHECK that it is stored lowercase, and the role CHECK from the previous step. Together they make email uniqueness case-insensitive, even for writes that skip the service.

Defaults are rules too. server_default writes the default into the table itself, so a bulk insert or raw SQL still gets a value; default applies only when the ORM inserts. Each default should be the safe one: an account starts active, must change its password, and is not demo data.

What your code has to do
  1. Declare nullability through the type: Mapped[str] is NOT NULL and Mapped[datetime | None] allows NULL. Only last_login_at is nullable, because NULL is the honest value for “never signed in”.
  2. Make the email unique exactly once, and add a named CHECK that it equals its lowercase form.
  3. Give the three flags database defaults: active, must change the password, not demo.
  4. Size the text columns for real values, 255 characters. An Argon2 hash is about 97, so a 64-character column would reject every insert.
  5. Add one composite index on role and active status, with an explicit name, for the staff list's filters.
  6. Compile the table to PostgreSQL DDL and read it before writing any migration.
Hint — the imports this step needs
Mapped[X | None]
Nullability from the annotation. SQLAlchemy 2.x derives NULL or NOT NULL from the type, so nullable= is redundant, and an explicit one that disagrees wins without a warning.
server_default
A default the database applies. With true() and false() from sqlalchemy, it becomes a SQL literal in the DDL.
CheckConstraint
A table-level rule. Its name is required here, because the ck naming convention builds the final name from it.
Index
An explicit index. Name composite indexes yourself: Index(None, ...) uses only the first column, so this one would become ix_users_role.
backend/app/modules/users/models.py 
class User(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    """A person who can sign in, with one role.

    Attributes:
        email: Sign-in name. Unique, and stored lowercase: the service
            lowercases it, and a CHECK constraint rejects anything else, so
            uniqueness is effectively case-insensitive.
        password_hash: Argon2 hash of the password. The plain password is
            never stored, logged, or returned.
        full_name: Name shown in the staff list and the audit log.
        role: The user's only role. Code checks permissions derived from
            it, never the role itself.
        is_active: False after an Admin deactivates the account. Inactive
            users get 401 on every request, including sign-in.
        must_change_password: True while the password is temporary. Every
            endpoint except the ones needed to change it returns 403
            ``PASSWORD_CHANGE_REQUIRED``.
        is_demo: True only for accounts created by ``seed-demo``, which are
            protected from changes and replaced by ``seed-demo --reset``.
        last_login_at: When the user last signed in, in UTC. None if they
            never have.
    """

    __tablename__ = "users"
    email: Mapped[str] = mapped_column(String(255), unique=True)
    password_hash: Mapped[str] = mapped_column(String(255))
    full_name: Mapped[str] = mapped_column(String(255))
    role: Mapped[Role] = mapped_column(string_enum(Role, name="role"))
    is_active: Mapped[bool] = mapped_column(Boolean, server_default=true())
    must_change_password: Mapped[bool] = mapped_column(Boolean, server_default=true())
    is_demo: Mapped[bool] = mapped_column(Boolean, server_default=false())
    last_login_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))

    # The composite index serves the staff list filters: role alone, or role
    # with is_active. Searching by name or email gets its own index with the
    # search query (IAM-5).
    __table_args__ = (
        CheckConstraint("email = lower(email)", name="email_lowercase"),
        Index("ix_users_role_is_active", "role", "is_active"),
    )

Step 04

A migration generated from the model, then read

Alembic's autogenerate compares Base.metadata with the database and writes the difference. A table is in that metadata only after its module is imported, so migrations/env.py must import the users models. That import exists only for its side effect, which is exactly what Ruff's --fix removes as unused; the next autogenerate would then find no table and write an empty migration.

The generated file is a draft until you have read it: the constraint names, the defaults, and a downgrade() that undoes upgrade() in reverse order. Then prove it works in both directions on your development database, before anything depends on it.

What your code has to do
  1. Import the users models in env.py, protected from Ruff, with the one-line comment every import in that file has.
  2. Update script.py.mako, the template every migration starts from, to the modern type syntax (str | Sequence[str] | None). The default template fails Ruff's UP007, so every new migration would fail CI.
  3. Generate the migration with a message, so its file name and docstring say what it does.
  4. Read it: pk_users, uq_users_email, ck_users_email_lowercase, the role column with create_constraint=True, the three server_defaults, and a downgrade() that drops the index before the table.
  5. Run alembic upgrade head, alembic downgrade -1 and alembic upgrade head again, then alembic check, which must find nothing left to generate.

Step 05

One factory, and a test for every constraint

A constraint you have never seen reject a row is one you can't be sure exists. These tests go below the service on purpose: they write through the ORM directly, and even with raw SQL, the way a seed script or a bug would, and they expect the database to refuse.

“Refused” isn't precise enough. pytest.raises(IntegrityError) accepts any integrity error, including one caused by a mistake in the test itself, so each test also names the constraint that must fire. psycopg reports it on the original error.

What your code has to do
  1. Put a factory in tests/factories.py that builds a valid, unsaved user, so each test changes only the field it is about.
  2. Test the duplicate email, the email with capitals and the case-only duplicate; each asserts the error's type and the constraint's name.
  3. Test an unknown role twice: through the ORM, where Python stops it before any SQL, and through raw SQL, where only the CHECK can.
  4. Keep only the failing call inside pytest.raises: the setup goes before it and the assertions after it.
  5. Give the factory a password hash that can never verify: a bcrypt value, because verify_password accepts only Argon2id. A test user built with it can't sign anyone in, whatever password is tried.
Hint — the imports this step needs

def test_two_users_cannot_share_an_email(db_session: Session) -> None:
    """A second user with the same email is rejected by ``uq_users_email``."""
    first_user = make_user()
    second_user = make_user()

    db_session.add(first_user)
    db_session.flush()

    db_session.add(second_user)

    with pytest.raises(IntegrityError) as exc_info:
        db_session.flush()

    orig = exc_info.value.orig
    assert isinstance(orig, psycopg.errors.UniqueViolation)
    assert orig.diag.constraint_name == "uq_users_email"

def test_the_database_rejects_an_unknown_role(db_session: Session) -> None:
    """Raw SQL with an unknown role is rejected by ``ck_users_role``.

    Raw SQL skips the ORM's check, so this proves the database protects the
    column on its own. The ``id`` is generated in SQL because the model's
    UUID default runs only in Python; without it the insert would fail on
    the NULL ``id`` before reaching the role CHECK.
    """
    with pytest.raises(IntegrityError) as exc_info:
        db_session.execute(
            text("""
                    INSERT INTO users (id, email, password_hash, full_name, role)
                    VALUES (gen_random_uuid(), :email, :password_hash, :full_name, :role)
                """),
            {
                "email": "test@example.com",
                "password_hash": FAKE_PASSWORD_HASH,
                "full_name": "Test User",
                "role": "superuser",
            },
        )

    orig = exc_info.value.orig
    assert isinstance(orig, psycopg.errors.CheckViolation)
    assert orig.diag.constraint_name == "ck_users_role"

Step 06

Test what the database stored, not what Python remembers

After a flush, the session still holds the Python object you built, and reading an attribute returns what is in memory, not what PostgreSQL stored. A test of server defaults has to refresh the object, or it checks nothing the database did. Some things can't be tested inside one transaction at all: now() returns the transaction's start time, so updated_at never changes within a test.

Comparisons need the same care. A StrEnum member equals its plain string, so user.role == Role.DOCTOR also passes when SQLAlchemy hands back "doctor"; is checks that you got the member itself.

What your code has to do
  1. Check the defaults after a refresh, with is True, is False and is None.
  2. Check each required column's NOT NULL with one parametrized test, and assert that the error names the same column.
  3. Check that the role reads back as a Role member, using is.
  4. Check what is stored with raw SQL, looking the row up by its id with a bound parameter: "doctor", the value, not the name.
  5. Run the file with -v and read the parametrized ids: [email], [password_hash], [full_name], [role].
