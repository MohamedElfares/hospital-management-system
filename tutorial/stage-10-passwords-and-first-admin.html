Step 01

Store a hash that is slow to guess, never the password

If the users table leaks, stored passwords would unlock every account at once, and every other site where people reused them. A hash can't be turned back into the password, but it can be guessed: hash a candidate, compare, repeat. A general-purpose hash such as SHA-256 is built to be fast, which is exactly what makes guessing cheap.

Argon2id is slow on purpose, and each attempt needs a block of memory, which takes away most of the advantage of guessing on graphics cards. Every hash also gets its own random salt, so two users with the same password get different hashes, and each one has to be attacked separately.

What your code has to do
  1. Expose two functions, hash and verify, and keep pwdlib behind them: no other module imports it.
  2. Build the hasher once, at module level, so every hash uses the same settings.
  3. Treat a stored hash in an unknown format as a failed match rather than an error, and log a warning that contains neither the hash nor the password.
  4. Compute one dummy hash at import time, with the same settings, for the sign-in in the next issue: an unknown email must take as long to reject as a wrong password.
  5. Measure it: verify once with Argon2id and once with SHA-256, and compare.
Hint — the imports this step needs
PasswordHash
pwdlib's hasher. PasswordHash.recommended() is Argon2id with 64 MB of memory, 3 passes and 4 lanes, written into every hash as m=65536,t=3,p=4.
UnknownHashError
Raised by verify for a hash pwdlib doesn't recognize. It raises instead of returning False, so a -> bool function has to catch it.
token_urlsafe
An unguessable random string, from secrets: the input of the dummy hash. random is for simulations; secrets is for anything security-related.
getLogger(__name__)
A logger named after the module, the same pattern as in errors.py and logging.py.

logger = logging.getLogger(__name__)

# One hasher for the whole process, so every hash uses the same settings.
_password_hash = PasswordHash.recommended()


def hash_password(password: str) -> str:
    """Hash a password for storage in ``users.password_hash``.

    Returns:
        The encoded hash, about 97 characters long.
    """
    return _password_hash.hash(password)


def verify_password(password: str, password_hash: str) -> bool:
    """Check a submitted password against a stored hash.

    Returns:
        True if the password matches the hash, and False if it doesn't or
        the hash is in an unsupported format.
    """
    try:
        return _password_hash.verify(password, password_hash)
    except UnknownHashError:
        logger.warning("Password hash uses an unknown or unsupported format")
        return False


# Sign-in verifies against this hash when the email matches no user, so an
# unknown email takes as long to reject as a wrong password and response
# times can't reveal which emails have accounts. It is built with
# hash_password, not pasted in, so it always has the same settings, and
# therefore the same cost, as real hashes.
_DUMMY_HASH = hash_password(secrets.token_urlsafe())

sha-256: 1.03 microseconds
ratio: about 54,947 times slower

The exact numbers depend on the machine; the ratio is the point. A real user signs in once and never notices the wait. An attacker trying a billion guesses pays it a billion times.

Step 02

Test the rules a hash must follow

These tests need no database: they call two functions and check the results. What makes them useful is the choice of inputs. A password that differs only by a trailing space catches code that trims input; a bcrypt hash catches a verify that crashes instead of answering.

One case checks that something is absent: the warning must not contain the hash. An absence check proves something only if the value couldn't appear by accident, and only if the code really took the path that could leak it.

What your code has to do
  1. Check the hash is Argon2id and not the password, and that the same password gets two different hashes that both verify.
  2. Check that near misses fail, each differing in exactly one way: letter case, and a trailing space. A case that differs in two ways can't tell you which rule held.
  3. Check that a unicode password and a very long one round-trip. bcrypt uses at most 72 bytes of a password; Argon2 has no such limit.
  4. Check that an unsupported hash returns False, logs a warning, and keeps the hash out of the log.
  5. Check that the dummy hash is Argon2id and that an ordinary password doesn't match it.
Hint — the imports this step needs
caplog
pytest's built-in log capture. caplog.at_level("WARNING") collects records during the block, and caplog.text is everything that was logged.
pytest.param(..., id=...)
A named case. id="trailing space" makes a failure report say which near miss broke.
_DUMMY_HASH
A private name, imported on purpose. A test may reach a module's internals when those internals are what it tests.

Step 03

Check the input once, before any rule runs

A user can be created from the command line now, and through the API later (IAM-5). Both need the same rules for the email, the name and the password, so the rules live in one Pydantic schema that both build before calling the service. The password rule comes from plan §8.1: 12 to 128 characters, and no composition rules, as NIST SP 800-63B recommends.

Two details decide whether the password survives validation intact. Stripping spaces is right for the name and wrong for the password, where a space is a character like any other, so it can't be a model-wide setting. And SecretStr hides the value when the model is printed, but Pydantic's ValidationError still contains the rejected input, so whatever reports those errors must print only the field and the message.

What your code has to do
  1. Validate the email's format and lowercase it, so it matches the database's CHECK.
  2. Strip the full name and require 1 to 255 characters, so a name of only spaces fails.
  3. Keep the password exactly as typed, limit it to 12–128 characters, and hide it when the model is printed.
  4. Accept only Role values for the role.
  5. Test every edge: 11 and 129 characters fail, 12 and 128 pass, and printing the whole model doesn't show the password.
Hint — the imports this step needs
EmailStr
A string that must be an email address, checked by email-validator.
AfterValidator
Runs a function after Pydantic's own checks. In AfterValidator(str.lower), str.lower already is a function that lowercases a string.
StringConstraints
Per-field string rules: strip, then check the length. Set per field, so the password is left alone.
SecretStr
Prints as **********. The value comes out only through get_secret_value().
ValidationError
Its errors() lists the problems. Each has a loc, the field, and a msg; tests compare loc to know which field failed.

class UserCreate(BaseModel):
    """Validated input for creating one user account.

    Attributes:
        email: Sign-in email, validated and lowercased.
        full_name: Display name, 1 to 255 characters after stripping.
        password: Plain password to hash, 12 to 128 characters.
        role: The new user's role.
    """

    email: Annotated[EmailStr, AfterValidator(str.lower)]
    full_name: Annotated[
        str,
        StringConstraints(
            strip_whitespace=True,
            min_length=1,
            max_length=255,
        ),
    ]
    password: SecretStr = Field(min_length=12, max_length=128)
    role: Role

Step 04

Queries in one place, and nowhere else

The repository is the only code that queries the users table, and it never commits: the service decides when a unit of work is finished. Keeping queries here means the service reads as rules, and a query can change without a hunt through the codebase.

Queries are built from the model's attributes. User.role == Role.ADMIN doesn't compare anything in Python; it builds SQL. A string can't do that: "role" == Role.ADMIN is evaluated by Python to False, and the query silently becomes WHERE false.

What your code has to do
  1. Find a user by an exact email, or return None. The caller passes an email that is already lowercase.
  2. Answer whether an active Admin exists, both conditions at once, without loading any rows.
  3. Add a new user to the session without writing anything; the service decides when.
  4. Test that an inactive Admin and an active Doctor don't count. Each test proves that one condition of the query is really there.
Hint — the imports this step needs
select
Builds a SELECT from the model. session.scalar(query) returns the first result, or None.
exists
An EXISTS subquery. PostgreSQL stops at the first matching row.
bool(...)
Makes the return type honest. session.scalar is typed as value-or-None, even though EXISTS always returns a row.
make_user

def get_by_email(session: Session, email: str) -> User | None:
    """Find the user with an exact email address.

    Returns:
        The matching user, or None if no account uses this email.
    """
    query = select(User).where(User.email == email)
    return session.scalar(query)


def active_admin_exists(session: Session) -> bool:
    """Tell whether at least one active Admin account exists.

    Returns:
        True if an Admin with ``is_active`` set exists, otherwise False.
    """
    query = select(exists().where((User.role == Role.ADMIN), (User.is_active.is_(True))))
    return bool(session.scalar(query))


def add(session: Session, user: User) -> None:
    """Register a new user with the session."""
    session.add(user)

Step 05

The rules, and exactly one commit

The service decides whether a user may be created. The usual duplicate is caught by looking the email up first, which gives a clear error without paying for a hash. Two requests can still pass that check together; the unique constraint rejects the second insert, and the service turns that IntegrityError into the same ConflictError. The rollback it needs undoes everything since the last commit, which is safe only because the service owns the whole transaction.

create-admin skips sign-in, so its power is limited to the case it exists for: nobody can sign in as an Admin. It works on a fresh database and when every Admin has been deactivated, and refuses otherwise. It forces the role to Admin and reuses the general function, so each rule is written once.

What your code has to do
  1. Refuse a taken email with a ConflictError, checking the returned value with if. try/except is for errors, and a bare except would report a lost database connection as “email exists”.
  2. Hash the password, save the user, and turn a constraint violation on flush into the same conflict, after a rollback, with the original error attached.
  3. End with one commit, and mark where the audit entry will go (Milestone 1.3).
  4. Create the first Admin only when no active Admin exists, with the role forced and no forced password change, by calling the general function.
  5. Test the race by making the email check miss, and after every refusal, prove that nothing extra was saved.
Hint — the imports this step needs
ConflictError
The project's 409 error, from app.core.errors. Its .message is safe to show.
raise ... from exc
Keeps the database error attached in logs and tracebacks, while callers see only the conflict.
model_copy
A copy of a Pydantic model, with the fields in update= replaced. It forces the role without changing the caller's object.
monkeypatch.setattr
Replaces an attribute for one test, and restores it afterwards. It works on repository.get_by_email because the service calls it through the module.

# One message for both ways a duplicate is detected, so callers can't tell
# the race case from the ordinary one.
_EMAIL_TAKEN = "A user with this email already exists."


def create_user(session: Session, data: UserCreate, *, must_change_password: bool) -> User:
    """Create a user account and commit it.

    Returns:
        The saved user, with its ID and database defaults set.


    Raises:
        ConflictError: If another account already uses the email. Nothing
            is saved in that case.
    """
    if repository.get_by_email(session, data.email) is not None:
        raise ConflictError(_EMAIL_TAKEN)

    password_hash = hash_password(data.password.get_secret_value())
    user = User(
        email=data.email,
        password_hash=password_hash,
        full_name=data.full_name,
        role=data.role,
        must_change_password=must_change_password,
    )

    repository.add(session, user)

    try:
        session.flush()
    except IntegrityError as exc:
        session.rollback()
        raise ConflictError(_EMAIL_TAKEN) from exc

    # TODO(1.3): audit user creation

    session.commit()
    return user


def create_first_admin(session: Session, data: UserCreate) -> User:
    """Create the first Admin, for the ``create-admin`` command.

    Returns:
        The saved Admin.


    Raises:
        ConflictError: If an active Admin already exists, or the email is
            taken. Nothing is saved in either case.
    """
    if repository.active_admin_exists(session):
        raise ConflictError("An active Admin already exists. Create more Admins through the API.")

    admin_data = data.model_copy(update={"role": Role.ADMIN})
    return create_user(session, admin_data, must_change_password=False)

def test_a_duplicate_caught_by_the_database_becomes_a_conflict(

Step 06

A command for the first Admin

There is no public sign-up, so on a new database nobody can sign in to create the first account. create-admin runs on a machine that has the database credentials, and that is the trust boundary: anyone who can run it could already change the database directly. Like a router, the command holds no rules. It collects input, opens a session, calls the service, and reports the result.

Where the password comes from matters. An argument is saved in the shell's history and shows in the process list; a hidden prompt leaves no copy. So the password is not a parameter at all: the command asks for it, twice.

What your code has to do
  1. Make create-admin a named command, with the email and full name as options that are asked for when left out.
  2. Read the password only from a hidden prompt, entered twice. There must be no way to pass it on the command line.
  3. Report validation errors as field and message only, never the error object, and state the password rule in plain words.
  4. Catch the project's domain errors, print their message to stderr and exit with code 1; on success, print the new Admin's email and ID.
  5. Test it with a runner that types into the prompts, pointed at the test database.
Hint — the imports this step needs
@app.callback()
Makes the app a group of named commands. With one command and no callback, Typer runs that command directly, and create-admin is rejected as an extra argument.
typer.prompt
Asks for a value. With hide_input=True and confirmation_prompt=True, the typing is hidden, the value is asked for twice, and the prompt repeats until the two entries match.
typer.Exit(code=1)
Stops the command with an exit code. A non-zero code tells scripts and CI that it failed.
AppError
The parent of every domain error. An entry point catches the broadest domain error, so errors added later are reported cleanly too.
CliRunner, nullcontext
Run the command inside a test. CliRunner feeds the prompts through input=; nullcontext(db_session) stands in for SessionLocal(), so the command uses the test session.
backend/app/cli.py 
app = typer.Typer(help="Hospital Management System maintenance commands.")

# Replaces Pydantic's SecretStr wording ("at least 12 items ..., not 5"),
# which is confusing and echoes the length of what was typed.
_PASSWORD_RULE = "must be 12 to 128 characters."


@app.callback()
def main() -> None:
    """Group the maintenance commands under one program."""


@app.command(help="Create the first Admin. The password is asked for twice and never shown.")
def create_admin(
    email: Annotated[str, typer.Option(prompt=True)],
    full_name: Annotated[str, typer.Option(prompt=True)],
) -> None:
    """Create the first Admin account from the terminal.

    Raises:
        typer.Exit: With code 1 when the input is invalid or the service
            refuses.
    """
    password = typer.prompt("Password", hide_input=True, confirmation_prompt=True)
    try:
        data = UserCreate(
            email=email,
            full_name=full_name,
            password=password,
            role=Role.ADMIN,
        )
    except ValidationError as exc:
        for error in exc.errors():
            field = ".".join(str(part) for part in error["loc"])
            message = _PASSWORD_RULE if field == "password" else error["msg"]
            typer.echo(f"{field}: {message}", err=True)
        raise typer.Exit(code=1)

    with SessionLocal() as session:
        try:
            admin = create_first_admin(session, data)
        except AppError as exc:
            typer.echo(exc.message, err=True)
            raise typer.Exit(code=1)

    typer.echo(f"Created Admin {admin.email} (id {admin.id})")


if __name__ == "__main__":
    app()
