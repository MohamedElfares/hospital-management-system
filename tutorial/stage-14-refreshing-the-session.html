Step 01

Finding a token, and holding its row

A refresh arrives with the raw token from the cookie. The server hashes it the same way as at sign-in and looks the row up by hash, which is unique and indexed. The lookup returns revoked and expired tokens too: the service has to see a revoked token to notice that it came back.

Two refreshes can arrive at the same moment with the same cookie, from two tabs or from a thief racing the real user. If both read the row as unused, both rotate it, and one token becomes two valid sessions. Reading the row with FOR UPDATE locks it until the transaction ends, so the second request waits and then sees the token already used.

What your code has to do
  1. Add a repository function that finds a token by its hash and returns None when no row matches.
  2. Lock the row it reads, until the service commits or rolls back.
  3. Return revoked and expired tokens as they are: deciding what they mean is the service's job.
  4. Test a match with a decoy token saved first, an unknown hash with a token in the table, and a revoked token that comes back with its revocation time.

def get_by_hash(session: Session, token_hash: str) -> RefreshToken | None:
    """Find the refresh token with a given hash and lock its row.

    Returns:
        The matching token, in whatever state it is, or None if no token
        has this hash.
    """
    statement = select(RefreshToken).where(RefreshToken.token_hash == token_hash).with_for_update()
    return session.scalar(statement)

Step 02

Ending every session in one statement

Sometimes all of a user's sessions must end at once: when a used token comes back, and later on password change and deactivation. One UPDATE covers any number of tokens. It is filtered to that user and to tokens not revoked yet, so an earlier revocation keeps its original time and the history of each token survives.

A bulk UPDATE goes straight to the database. Objects the session already loaded can still show the old values, so a test that checks the result has to query again rather than trust an object it held before.

What your code has to do
  1. Revoke every unrevoked token of one user in a single statement, with a time the service passes in.
  2. Leave tokens that are already revoked, and every other user's tokens, untouched.
  3. Commit nothing: the service owns the transaction.
  4. Test all of a user's tokens, a bystander's token, and a token revoked earlier, reading each back with a new query.

def revoke_all_for_user(session: Session, user_id: uuid.UUID, revoked_at: datetime) -> None:
    """Revoke every refresh token of one user that isn't revoked yet."""
    statement = (
        update(RefreshToken)
        .where(RefreshToken.user_id == user_id, RefreshToken.revoked_at.is_(None))
        .values(revoked_at=revoked_at)
    )

    session.execute(statement)

Step 03

One way to issue tokens

Sign-in and refresh end the same way: a new random refresh token, a row holding only its hash, and a new access token. Moving that into one private function keeps the two from drifting apart. They differ in one thing, the expiry, so the caller passes it: sign-in starts a new window, and refresh keeps the old one.

The function adds the row without committing, so a refresh can never save the new token without also revoking the old one. It also returns the new row, because refresh needs its id to link the old token to it.

What your code has to do
  1. Rename the sign-in result to a name that fits both cases, still a frozen dataclass and not a response schema.
  2. Write one private function that generates the token, adds a row holding only its hash, and signs the access token, with the expiry as a parameter.
  3. Return the tokens and the new row, and commit nothing.
  4. Rewrite sign-in on top of it, and run the sign-in tests unchanged to prove nothing moved.

@dataclass(frozen=True)
class IssuedTokens:
    """The tokens issued by a sign-in or a refresh.

    Attributes:
        access_token: The signed JWT for the ``Authorization: Bearer``
            header, returned in the response body.
        refresh_token: The raw refresh token. It goes only into the
            ``HttpOnly`` cookie, never into a response body or a log; the
            database holds only its hash.
    """

    access_token: str
    refresh_token: str


def _issue_tokens(
    session: Session,
    user: User,
    expires_at: datetime,
) -> tuple[IssuedTokens, RefreshToken]:
    """Create a new access token and refresh token for a user.

    Returns:
        The tokens to send to the client, and the new refresh token's row,
        which refresh links the revoked token to.
    """
    raw_refresh_token = generate_refresh_token()
    refresh_token_row = RefreshToken(
        user_id=user.id,
        token_hash=hash_refresh_token(raw_refresh_token),
        expires_at=expires_at,
    )

    repository.add(session, refresh_token_row)

    # Keywords, because both fields are strings: swapped positions would put
    # the raw refresh token in the response body.
    issued_tokens = IssuedTokens(
        access_token=create_access_token(user.id),
        refresh_token=raw_refresh_token,
    )

    return issued_tokens, refresh_token_row

Step 04

Each token works once, inside a fixed window

Refresh exchanges the cookie for a new access token and a new refresh token, and revokes the presented one, linking it to its replacement through replaced_by_id. The new token keeps the old expiry, so a session never outlives the 7 days that began at sign-in: a stolen cookie has a hard limit even if the thief keeps refreshing (ADR-0004).

A token that is already revoked means a copy exists, and the server can't tell the real user from a thief, so it revokes every token of that user and logs a warning, never the token. That revocation is committed before the 401, because a failed request is rolled back and would otherwise save nothing. It is checked before expiry, so an old stolen token still raises the alarm. Stage 16 narrows this rule to tokens that were rotated, after a password change shows why.

What your code has to do
  1. Refuse a missing cookie and an unknown hash with the same error and message as every other failure.
  2. When the token is revoked: log a warning with the user and token ids, revoke every token of that user, commit, then raise.
  3. Refuse an expired token with no alarm, then load the user and refuse a missing or inactive account.
  4. On success, issue a new pair with the old expiry, flush, then revoke the old row, set its replaced_by_id, and commit once.
  5. Leave last_login_at alone, and let a pending password change through: the web app needs a session to show the change-password screen.

def refresh(session: Session, raw_refresh_token: str | None) -> IssuedTokens:
    """Exchange a refresh token for a new access token and refresh token.

    Returns:
        The new access token for the response body and the new raw refresh
        token for the cookie.

    Raises:
        AuthenticationError: If the token is missing, unknown, already
            revoked, or expired, or its user is missing or deactivated. The
            message is the same in every case.
    """
    if not raw_refresh_token:
        raise AuthenticationError(_INVALID_TOKEN)

    presented_token = repository.get_by_hash(session, hash_refresh_token(raw_refresh_token))

    if presented_token is None:
        raise AuthenticationError(_INVALID_TOKEN)

    now = datetime.now(UTC)

    # A revoked token presented again means a copy exists. Checked before
    # expiry so an old stolen token still raises the alarm, and committed
    # before raising because a failed request would otherwise save nothing.
    if presented_token.revoked_at is not None:
        logger.warning(
            "Refresh token reuse detected (user_id=%s, token_id=%s)",
            presented_token.user_id,
            presented_token.id,
        )

        repository.revoke_all_for_user(session, presented_token.user_id, now)

        # TODO(1.3): audit the reuse and the mass revocation (plan §8.6)

        session.commit()

        raise AuthenticationError(_INVALID_TOKEN)

    # No alarm and no revocation: tokens running out is normal.
    if presented_token.expires_at <= now:
        raise AuthenticationError(_INVALID_TOKEN)

    # Deactivation also revokes every token (plan §8.1); checking the account
    # here means a token that escaped that still can't start a new session.
    user = get_user_by_id(session, presented_token.user_id)

    if user is None or not user.is_active:
        raise AuthenticationError(_INVALID_TOKEN)

    # The old expiry, not a new one: refreshing never extends a session.
    issued_tokens, new_token_row = _issue_tokens(
        session,
        user,
        presented_token.expires_at,
    )

    # The new row gets its id on insert; flush so the link below isn't None.
    session.flush()

    presented_token.revoked_at = now
    presented_token.replaced_by_id = new_token_row.id

    session.commit()

    return issued_tokens

Step 06

Testing every failure, and the alarm

Five failures must look the same and write nothing: no cookie, an empty one, an unknown token, an expired one, and a deactivated owner. Some cases need a saved token and some don't, so the parametrize list holds case names, and a helper turns each name into the value to present. An unknown name raises, so a typo can't quietly become the “missing” case.

Reuse is the one failure that writes, so it has its own tests: the other session is revoked, the revocation survives a rollback, and the warning names the user but never the token. The rollback test is the one that catches a missing commit: without the rollback, the uncommitted change is still in the session, and the first test passes anyway.

What your code has to do

  2. Test that each one raises the same message and adds or revokes no row.
  3. Test that presenting a revoked token revokes the user's other token.
  4. Roll the session back after the error, as a failed request's is, and check the revocation is still there.
  5. Capture the logs and check for exactly one warning, with the user id and without the raw token.

def _present_token(db_session: Session, user: User, case: str) -> str | None:
    """Build the refresh token value a test presents for one failure case.

    Returns:
        The raw token to pass to ``refresh``, or None for a missing cookie.

    Raises:
        ValueError: If ``case`` isn't a known case name.
    """
    if case == "missing":
        return None
    if case == "empty":
        return ""
    if case == "unknown":
        return generate_refresh_token()  # never saved, so no row has its hash
    if case == "expired":
        expires_at = datetime.now(UTC) - timedelta(seconds=1)
        return _save_refresh_token(db_session, user, expires_at=expires_at)
    if case == "inactive-user":
        raw_refresh_token = _save_refresh_token(db_session, user)
        user.is_active = False
        db_session.flush()
        return raw_refresh_token
    raise ValueError(f"Unknown case: {case}")

Step 07

The endpoint reads the cookie

POST /auth/refresh is Public with the cookie: it must work when the access token has expired or is gone, so it takes no Authorization header. The browser sends the cookie by itself, only to /api/v1/auth paths, and SameSite=Strict keeps other sites from sending it.

The cookie parameter defaults to None. Without the default, FastAPI would answer a request with no cookie with a 422 validation error before the service ran, instead of the standard 401. A failed refresh sets no cookie, because the error handler builds a new response.

What your code has to do
  1. Read the cookie by its name, defaulting to None, and pass it to the service.
  2. On success, set the new refresh cookie and return the access token in the body.
  3. Give the route a summary and document the 401.
  4. Test 200 with a new cookie and its flags, that the new token never appears in the body, and 401 without a cookie and with an unknown one.
  5. Test reuse over HTTP: refresh once, put the old cookie back, refresh with it, then check that the new cookie is dead too.

            ``AUTHENTICATION_FAILED``.
    """
    issued_tokens = service.refresh(db, refresh_token)
    set_refresh_cookie(response, issued_tokens.refresh_token)

    return TokenResponse(access_token=issued_tokens.access_token)

def test_reusing_an_old_cookie_signs_out_every_session(user: User, client: TestClient) -> None:
    """Replaying a replaced cookie fails and kills the newer cookie as well."""
    login_response = client.post(LOGIN_URL, data={"username": user.email, "password": PASSWORD})

    assert login_response.status_code == 200

    old_token = login_response.cookies[REFRESH_COOKIE_NAME]
    refresh_response = client.post(REFRESH_URL)

    assert refresh_response.status_code == 200

    new_token = refresh_response.cookies[REFRESH_COOKIE_NAME]

    client.cookies.clear()
    client.cookies.set(REFRESH_COOKIE_NAME, old_token, path="/api/v1/auth")
    reuse_response = client.post(REFRESH_URL)
    reuse_error = reuse_response.json()["error"]

    client.cookies.clear()
    client.cookies.set(REFRESH_COOKIE_NAME, new_token, path="/api/v1/auth")
    after_reuse_response = client.post(REFRESH_URL)
    after_reuse_error = after_reuse_response.json()["error"]

    assert reuse_response.status_code == 401
    assert reuse_error["code"] == "AUTHENTICATION_FAILED"
    assert reuse_error["message"] == "Invalid or expired token."
    assert after_reuse_response.status_code == 401
    assert after_reuse_error["code"] == "AUTHENTICATION_FAILED"
    assert after_reuse_error["message"] == "Invalid or expired token."
