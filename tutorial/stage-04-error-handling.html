Errors in one format

Services raise domain errors, and four handlers turn every failure, planned or not, into one JSON body the client can rely on.

Installed so far

Step 01

One list of every error code

The frontend decides what to do after a failure by reading a code, such as INSUFFICIENT_STOCK, never by comparing English sentences. That makes the codes a public contract, and a contract typed by hand in twenty places will eventually contain a typo that nobody notices until a screen silently stops reacting.

Collect every code in one place, so a misspelled code fails the moment the module loads.

What your code has to do
  1. Define every code the API can return in one enum: one per HTTP status you use, plus the specific situations from plan §11 (PASSWORD_CHANGE_REQUIRED, INVALID_STATUS_TRANSITION, APPOINTMENT_SLOT_TAKEN, INSUFFICIENT_STOCK, ACTIVATION_FAILED), and VALIDATION_ERROR, METHOD_NOT_ALLOWED and INTERNAL_ERROR.
  2. Make each member usable as a plain string, so it serializes to JSON as "NOT_FOUND" with no conversion.
  3. Give every member a value identical to its name.
  4. Prove it: json.dumps({"code": ErrorCode.NOT_FOUND}) gives {"code": "NOT_FOUND"}.
Hint — the imports this step needs
StrEnum
An enum whose members are also strings. Each member compares equal to its text and needs no conversion for JSON, which is exactly what a code sent to a client needs.
backend/app/core/errors.py

Step 02

A base error that services raise instead of HTTP errors

Services must not know about HTTP: CLAUDE.md forbids HTTPException in them. A service says "this patient doesn't exist" by raising a domain error, and the HTTP layer decides it means 404.

The base class sets the default code for its kind of error; one particular error can carry a more specific one. Get the defaults wrong and every error reaches the client with "code": null.

What your code has to do
  1. Create a base exception with a class-level status and code (500, INTERNAL_ERROR) that subclasses will override.
  2. Accept a required message, plus an optional code and optional details that must be passed by name, so a list can never land in code by position.
  3. Keep the class default code unless a code was actually given. Storing None on the instance would hide the class value.
  4. Make details always a list, and a new one for each error. A list written as a default value is created once and shared by every error.
  5. Let Exception do its own setup, so str(error) gives the message.
  6. Prove it: NotFoundError("x").code is the class default, and two errors created without details don't share a list.
Hint — what this step uses
Any
The type of values inside details. Details can hold IDs, numbers or names, so the dict values are left open.
super().__init__
Runs the parent class's setup. A subclass that writes its own __init__ replaces the parent's, so Exception's setup only runs if you call it.
backend/app/core/errors.py 
class AppError(Exception):
    """Base class for every error a service raises on purpose.

    Attributes:
        status_code: HTTP status returned for this class of error.
        code: Machine-readable code. The class default is used unless the
            caller passes a more specific one.
        message: Human-readable explanation, safe to show to the user.
        details: Extra structured information, such as which medicines are
            short. Always a list, empty when there is nothing to add.
    """

    status_code: int = 500
    code: str = ErrorCode.INTERNAL_ERROR

    def __init__(
        self,
        message: str,
        *,
        code: str | None = None,
        details: list[dict[str, Any]] | None = None,
    ) -> None:
        """Create an error with a message and optional code and details."""
        super().__init__(message)
        self.message = message
        if code is not None:
            self.code = code
        self.details = details if details is not None else []

Step 03

One class per HTTP status

Each HTTP status gets one subclass; the specific situation goes in code. So a new situation, such as a taken appointment slot, never needs a new class, only a new code on ConflictError.

Because exception handlers also match subclasses, one handler registered for the base class will serve all of them, including any you add later.

What your code has to do
  1. Add one subclass each for 400, 401, 403, 404, 409 and 429, each with its own status and default code.
  2. Give them no __init__ of their own: they inherit the base class's.
  3. Order them by status code, so the file reads like the table in plan §11.
  4. Prove it: ConflictError("x", code=ErrorCode.INSUFFICIENT_STOCK) has status 409 and the specific code.
backend/app/core/errors.py 
class BadRequestError(AppError):
    """The request is well formed but can't be processed (400)."""

    status_code: int = 400
    code: str = ErrorCode.BAD_REQUEST


class AuthenticationError(AppError):
    """The caller isn't authenticated (401)."""

    status_code: int = 401
    code: str = ErrorCode.AUTHENTICATION_FAILED


class PermissionDeniedError(AppError):
    """The caller is authenticated but not allowed to do this (403)."""

    status_code: int = 403
    code: str = ErrorCode.PERMISSION_DENIED


class NotFoundError(AppError):
    """The resource doesn't exist, or the user may not see it (404)."""

    status_code: int = 404
    code: str = ErrorCode.NOT_FOUND


class ConflictError(AppError):
    """A business rule blocks the action (409)."""

    status_code: int = 409
    code: str = ErrorCode.CONFLICT


class RateLimitedError(AppError):
    """Too many attempts in a short time (429)."""

    status_code: int = 429
    code: str = ErrorCode.RATE_LIMITED

Step 04

One place that shapes every error body

Plan §11 fixes the shape of every error: {"error": {"code", "message", "details", "request_id"}}. Four handlers will produce it. If each builds the dictionary itself, the four copies drift apart the first time the format changes.

This function also runs while something has already gone wrong, so it must never raise an error of its own. A crash here replaces your tidy JSON with a raw 500.

What your code has to do
  1. Build the whole response from a request, a status, a code, a message and optional details.
  2. Return details as a list even when none was given, because the frontend loops over it.
  3. Read the request ID from the request's state without failing when it isn't there. The middleware that sets it comes in the next stage, so for now it is missing, and the body must show null.
  4. Keep the function private to the module: only the handlers call it.
  5. Prove it: calling it with a bare Starlette Request({"type": "http"}) returns a 404 with "request_id":null.
Hint — the imports this step needs
Request
The incoming request. Its state is where the middleware will store the request ID.
JSONResponse
A response with a JSON body and a status code. Its content is a plain dict; FastAPI turns it into JSON.
getattr
Built-in: reads an attribute with a fallback. getattr(obj, "name", None) returns None instead of raising AttributeError.
backend/app/core/errors.py 
def _error_response(
    request: Request,
    status_code: int,
    code: str,
    message: str,
    details: list[dict[str, Any]] | None = None,
) -> JSONResponse:
    """Build a response in the standard error format.

    Returns:
        A JSON response with body
        ``{"error": {"code", "message", "details", "request_id"}}``.
    """
    return JSONResponse(
        status_code=status_code,
        content={
            "error": {
                "code": code,
                "message": message,
                "details": details if details is not None else [],
                "request_id": getattr(request.state, "request_id", None),
            }
        },
    )

Step 05

Your own errors, and input that fails validation

Two handlers cover the errors that come from your side of the app. The first turns any domain error into its response in one line, because the exception already carries everything needed.

The second replaces FastAPI's default 422, which has a real problem: it echoes back the invalid input. For a login form, that is the password, returned in the response body.

What your code has to do
  1. Answer any domain error with its own status, code, message and details, through the shared function from step 04.
  2. Answer input validation failures with 422, VALIDATION_ERROR, a general message, and one detail per problem.
  3. Give each detail a readable field path such as body.email, or body.items.0.quantity for a list position, plus the message and the error type.
  4. Never copy Pydantic's input into the response.
  5. Report every problem, not only the first: a body missing both email and password lists two details.
Hint — the import this step needs
RequestValidationError
Raised by FastAPI when a request doesn't match its schema, before your route runs. exc.errors() lists the problems.
backend/app/core/errors.py 
async def _handle_app_error(request: Request, exc: AppError) -> JSONResponse:
    """Convert a domain error raised by a service into its HTTP response.

    Returns:
        The error response with the exception's own status and code.
    """
    return _error_response(request, exc.status_code, exc.code, exc.message, exc.details)


async def _handle_validation_error(request: Request, exc: RequestValidationError) -> JSONResponse:
    """Convert a Pydantic input validation failure into a 422 response.

    Returns:
        A 422 response with code ``VALIDATION_ERROR`` and one detail per
        problem.
    """
    details: list[dict[str, Any]] = []

    for error in exc.errors():
        loc = error["loc"]
        details.append(
            {
                "field": ".".join(str(part) for part in loc),
                "message": error["msg"],
                "type": error["type"],
            }
        )

    return _error_response(
        request,
        status_code=422,
        code=ErrorCode.VALIDATION_ERROR,
        message="The request contains invalid data.",
        details=details,
    )

Step 06

Framework errors, crashes, and wiring it all up

Two kinds of error never pass through your services. Starlette raises its own HTTPException for an unknown URL, a known URL with the wrong method, and FastAPI's login helper. Anything nobody planned for is a bug, and needs the opposite treatment from everything else: full detail in the log, as little as possible in the response.

The exception text of a crash can contain SQL, file paths or patient data, so it must never reach the client (plan §12).

What your code has to do
  1. Map Starlette's statuses to codes, with a fallback that is always an error code: INTERNAL_ERROR for 5xx, BAD_REQUEST otherwise. A status number there breaks the contract.
  2. Keep the exception's headers on the response: a 405 must say which methods are Allowed, and a 401 from the login helper carries WWW-Authenticate.
  3. Make the message always a string.
  4. For unexpected errors, log the full traceback with the request ID, and respond with 500, INTERNAL_ERROR and a fixed message.
  5. Provide one public function that attaches all four handlers to an app. main.py will call it.
Hint — the imports this step needs
HTTPException as StarletteHTTPException
Starlette's HTTP error. Register this one, not FastAPI's: FastAPI's is a subclass, so Starlette's handler catches both, but not the other way round.
FastAPI
The application type, which register_exception_handlers receives.
logging
The standard logging module. logger.exception(...) writes a message plus the traceback of the error being handled.
backend/app/core/errors.py 
# Maps the statuses Starlette and FastAPI's security helpers raise to error codes.
_STATUS_TO_ERROR_CODE: dict[int, ErrorCode] = {
    400: ErrorCode.BAD_REQUEST,
    401: ErrorCode.AUTHENTICATION_FAILED,
    403: ErrorCode.PERMISSION_DENIED,
    404: ErrorCode.NOT_FOUND,
    405: ErrorCode.METHOD_NOT_ALLOWED,
    409: ErrorCode.CONFLICT,
    422: ErrorCode.VALIDATION_ERROR,
    429: ErrorCode.RATE_LIMITED,
}


async def _handle_http_exception(request: Request, exc: StarletteHTTPException) -> JSONResponse:
    """Convert Starlette's HTTP errors into the standard error format.

    Returns:
        An error response with the same status and any headers the exception
        carried.
    """
    status_code: int = exc.status_code
    default_code: ErrorCode = (
        ErrorCode.INTERNAL_ERROR if status_code >= 500 else ErrorCode.BAD_REQUEST
    )
    code: ErrorCode = _STATUS_TO_ERROR_CODE.get(status_code, default_code)
    message: str = str(exc.detail)
    headers = exc.headers

    response: JSONResponse = _error_response(request, status_code, code, message)

    if headers:
        response.headers.update(headers)

    return response


async def _handle_unexpected_error(request: Request, exc: Exception) -> JSONResponse:
    """Log an unplanned exception and return a generic 500 response.

    Returns:
        A 500 response with code ``INTERNAL_ERROR`` and a generic message.
    """
    request_id = getattr(request.state, "request_id", None)
    logger.exception("Unhandled error (request_id=%s)", request_id)

    return _error_response(
        request,
        status_code=500,
        code=ErrorCode.INTERNAL_ERROR,
        message="An unexpected error occurred.",
    )


def register_exception_handlers(app: FastAPI) -> None:
    """Attach all four error handlers to the application."""
    app.add_exception_handler(AppError, _handle_app_error)
    app.add_exception_handler(RequestValidationError, _handle_validation_error)
    app.add_exception_handler(StarletteHTTPException, _handle_http_exception)
    app.add_exception_handler(Exception, _handle_unexpected_error)
