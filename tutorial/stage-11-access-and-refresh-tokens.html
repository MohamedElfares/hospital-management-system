Step 01

A token that proves who is calling, and nothing more

Once someone has signed in, every request has to say who is making it. Sending the password each time would mean keeping it in the browser and paying for an Argon2 check on every call. Instead, sign-in (Stage 12) hands out an access token: a JSON Web Token whose payload names the user and whose HMAC signature proves the server wrote it. A JWT is signed, not encrypted, so anyone holding it can read it; only the holder of JWT_SECRET_KEY can make one that verifies.

Verifying is where tokens go wrong. The token's own header names its algorithm, and an attacker writes that header. PyJWT checks exp only when the claim is present, so a token without one would never expire. The decoder therefore fixes the algorithm itself, requires every claim it relies on, and turns every failure into the same 401.

What your code has to do
  1. Create a token with exactly three claims: sub (the user's ID as a string), iat, and exp one configured lifetime later. Nothing else, because anyone holding the token can read it, and a role or an email in it would go stale.
  2. Sign it with HS256 and the key from the settings, read inside the function. The algorithm is a constant in code, not a setting: it is a security decision, not a value that changes between environments.
  3. Decode with only HS256 allowed and all three claims required, so a token that names none as its algorithm, or one without exp, is rejected.
  4. Return the subject as a UUID, and turn every failure, PyJWT's errors and a subject that isn't a UUID alike, into one AuthenticationError with one message.
  5. Decode a fresh token without its key, and look at what anyone holding it can read.
Hint — what this step uses
jwt
PyJWT. jwt.encode(claims, key, algorithm=...) signs; jwt.decode(token, key, algorithms=[...], options=...) checks the signature, then exp and iat, and returns the claims. It turns datetime values into Unix timestamps for you.
jwt.InvalidTokenError
The base class of every PyJWT verification error: bad signature, expired, missing claim, disallowed algorithm, malformed input. One except covers them all.

How a SecretStr gives up its value. The key is wrapped so it never prints; PyJWT needs the string itself and raises TypeError: Expected a string or bytes value when handed the wrapper.

Parses the subject back into an ID. It raises ValueError for anything that isn't a UUID, such as "admin", which is why the decoder catches that too.
AuthenticationError

def create_access_token(user_id: uuid.UUID) -> str:
    """Create a signed access token for a user who has just signed in.

    Returns:
        The encoded token, in the form ``header.payload.signature``. Never
        logged.
    """
    settings = get_settings()
    sub = str(user_id)
    iat = datetime.now(UTC)
    exp = iat + timedelta(minutes=settings.access_token_expire_minutes)
    claims: dict[str, Any] = {"sub": sub, "iat": iat, "exp": exp}

    return jwt.encode(
        claims, key=settings.jwt_secret_key.get_secret_value(), algorithm=_JWT_ALGORITHM
    )


def decode_access_token(token: str) -> uuid.UUID:
    """Verify an access token and return the ID of the user it names.

    Returns:
        The user ID from the ``sub`` claim.

    Raises:
        AuthenticationError: If the token is malformed, tampered with,
            signed with another key or algorithm, expired, or missing a
            required claim, or if its subject isn't a UUID.
    """
    try:
        payload: dict[str, Any] = jwt.decode(
            token,
            key=get_settings().jwt_secret_key.get_secret_value(),
            algorithms=[_JWT_ALGORITHM],
            options={"require": ["sub", "iat", "exp"]},
        )
        return uuid.UUID(payload["sub"])
    except (jwt.InvalidTokenError, ValueError):
        # A bad token is ordinary client input, not a server fault, so
        # PyJWT's exception is left out of the chain rather than attached
        # to the error as its cause.
        raise AuthenticationError("Invalid or expired token.") from None

Step 02

Test every way a token can be wrong

Most of these tests are rejections, and a rejection test is easy to fool: if the token it builds is wrong in two ways, it passes as long as either is caught. So each test starts from a token that is valid in every way and changes exactly one thing. A helper builds that token, and a control test proves the helper's untouched token is accepted, so every rejection can be blamed on its one change.

The algorithm is written out in the tests instead of imported from security.py. A test that imported the constant would agree with any change to it; written out, a change to the algorithm fails here first.

What your code has to do
  1. Write a helper that builds a valid token from the same claims as create_access_token, then applies overrides, removes omitted claims, and signs with a chosen key and algorithm.
  2. Add a control test: the helper's token, unchanged, decodes to the user ID it carries.
  3. Check that the round trip returns a UUID equal to the input, and that a token holds exactly sub, iat and exp, with exp - iat equal to the configured lifetime.
  4. Reject, one change at a time: expired, another key, another token's payload under a genuine header and signature, alg: none, no exp, a subject that isn't a UUID, and input that isn't a JWT at all.
  5. In every rejection, check the message as well as the type, so the test proves the generic 401 and not some other AuthenticationError.
Hint — what this step uses
**overrides
Keyword arguments gathered into a dict. _make_token(exp=past) replaces one claim, and omit=("exp",) removes one.
algorithm="none"
An unsigned token. PyJWT insists the key is None for it and raises InvalidKeyError otherwise, which is why the helper picks the key by algorithm.
token.split(".")
A JWT's three parts: header, payload and signature, each base64url-encoded. Putting another token's middle part between a real header and signature is how someone would try to forge another user's claims.
secrets.token_urlsafe(32)
A key nobody else has, for the wrong-key test.
pytest.raises(...) as exc_info
Catches the expected exception and keeps it. exc_info.value.message is the text the API would send.

def _make_token(
    *,
    key: str | None = None,
    algorithm: str = JWT_ALGORITHM,
    omit: tuple[str, ...] = (),
    **overrides: Any,
) -> str:
    """Build an access token that is valid except for what the caller changes.

    Returns:
        The encoded token.

    Raises:
        KeyError: If ``omit`` names a claim that isn't present, so a typo
            fails the test instead of silently building a valid token.
    """
    settings = get_settings()
    now = datetime.now(UTC)
    claims: dict[str, Any] = {
        "sub": str(uuid.uuid4()),
        "iat": now,
        "exp": now + timedelta(minutes=settings.access_token_expire_minutes),
    }
    claims.update(overrides)
    for name in omit:
        del claims[name]

    # PyJWT refuses any key for alg "none"; it must be None.
    if algorithm == "none":
        signing_key = None
    elif key is not None:
        signing_key = key
    else:
        signing_key = settings.jwt_secret_key.get_secret_value()

    return jwt.encode(claims, signing_key, algorithm=algorithm)

def test_an_access_token_holds_only_sub_iat_and_exp() -> None:
    """A token carries exactly ``sub``, ``iat``, and ``exp``, with correct values."""
    settings = get_settings()
    jwt_secret_key = settings.jwt_secret_key.get_secret_value()
    access_token_expire_minutes = settings.access_token_expire_minutes

    user_id = uuid.uuid4()

    before = int(datetime.now(UTC).timestamp())
    token = create_access_token(user_id)
    after = int(datetime.now(UTC).timestamp())

    payload = jwt.decode(token, key=jwt_secret_key, algorithms=[JWT_ALGORITHM])

    assert set(payload) == {"sub", "iat", "exp"}
    assert payload["sub"] == str(user_id)
    assert payload["iat"] >= before
    assert payload["iat"] <= after
    assert payload["exp"] - payload["iat"] == access_token_expire_minutes * 60

def test_a_tampered_access_token_is_rejected() -> None:

Step 03

A refresh token is random, and only its hash is kept

An access token expires in 15 minutes, so a stolen one is not useful for long, but nobody wants to sign in every quarter of an hour. A refresh token fixes that: a long-lived value the client trades for a new access token. Unlike a JWT it carries no data at all. It is 32 random bytes, valid only while a row in the database says so, which is what will let sign-out and deactivation end a session.

The database keeps a SHA-256 hash of the token, so a leaked table gives nobody a usable token. Passwords needed a slow, salted hash because people choose guessable ones; 256 random bits can't be guessed however fast the hash is. Leaving out the salt is deliberate too: the same token must always give the same hash, because the hash is how a refresh will find its row.

What your code has to do
  1. Generate the token from the operating system's secure random source, 32 bytes, encoded so it fits in a cookie without escaping.
  2. Hash it with plain SHA-256 to 64 lowercase hex characters, the same every time for the same token.
  3. Test that a hundred tokens are all different, and that a token is URL-safe and at least 43 characters long.
  4. Test the hash against the published SHA-256 test vector for "abc", so a salt or another algorithm fails a test before it signs every user out.
  5. Test that a hundred different tokens give a hundred different hashes, and that a hash has exactly the column's shape.
Hint — the imports this step needs
secrets.token_urlsafe
Random bytes, base64url-encoded. 32 bytes become 43 characters, all letters, digits, - and _, which a cookie carries as they are. random is predictable and is never used for tokens.
hashlib.sha256
The standard library's SHA-256. It hashes bytes, so the token is encoded first; .hexdigest() gives the 64-character text the column stores.
re.fullmatch
Matches the whole string or nothing. re.match would accept a longer string that only starts with the right characters.
backend/app/core/security.py 
def generate_refresh_token() -> str:
    """Create a new random refresh token.

    Returns:
        The raw token, about 43 characters long. It is sent to the client
        once, in the cookie, and never stored or logged.
    """
    return secrets.token_urlsafe(32)


def hash_refresh_token(token: str) -> str:
    """Hash a refresh token for storage in ``refresh_tokens.token_hash``.

    Returns:
        The hash as 64 lowercase hexadecimal characters.
    """
    return hashlib.sha256(token.encode()).hexdigest()

Step 04

A table that knows which sessions are alive

Each refresh token gets a row: whose it is, its hash, when it expires, and whether it was revoked. A token is usable only while revoked_at is NULL and expires_at is in the future. Revoking sets a time instead of deleting the row, so the history is still there when something looks wrong.

The last column prepares for rotation, later in this issue: each refresh revokes the old token and links it to its replacement, and if a revoked token is presented again, someone has a copy, so every token of that user is revoked (plan §8.1). The link points at another row of the same table, and when that row goes, the link is cleared instead of deleting the older token with it.

What your code has to do
  1. Reference the user with a foreign key that deletes the user's tokens with the user, and index it: every query for a user's tokens filters on it.
  2. Store the hash in a column exactly as long as a SHA-256 hex digest, and make it unique, because a refresh finds its row by this value.
  3. Give expires_at no default, so a token saved without an expiry fails instead of quietly getting one, and make revoked_at optional.
  4. Point replaced_by_id at this same table: optional, indexed, and cleared when the replacement is deleted.
  5. Store both times as timezone-aware UTC instants, and reuse the ID and timestamp mixins from Stage 03.
Hint — the imports this step needs
ForeignKey(..., ondelete=...)

class RefreshToken(UUIDPrimaryKeyMixin, TimestampMixin, Base):
    """One refresh token issued to a user, stored as a hash.

    Attributes:
        user_id: The user the token signs in. Deleting the user deletes
            their tokens (ON DELETE CASCADE); in the app users are only
            deactivated, but ``seed-demo --reset`` and tests delete them.
        token_hash: SHA-256 of the token as 64 hex characters. Unique,
            because each refresh finds its row by this value. A fast hash
            is safe here, unlike for passwords, because the token is 256
            random bits and can't be guessed; it also has no salt, so the
            same token always gives the same hash and can be looked up.
        expires_at: When the token stops working, in UTC. Set by the
            service from ``REFRESH_TOKEN_EXPIRE_DAYS``; there is no default
            so a missing value fails instead of picking a lifetime.
        revoked_at: When the token was revoked by rotation, sign-out, or
            reuse detection. None while the token is still usable.
        replaced_by_id: The token issued when this one was rotated. None
            if it was never rotated, so a revoked row with no replacement
            was ended by sign-out or reuse detection. Cleared if the
            replacement row is deleted (ON DELETE SET NULL).
    """

    __tablename__ = "refresh_tokens"

    user_id: Mapped[uuid.UUID] = mapped_column(
        ForeignKey("users.id", ondelete="CASCADE"),
        index=True,
    )
    token_hash: Mapped[str] = mapped_column(
        String(64),
        unique=True,
    )
    expires_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
    )
    revoked_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True),
    )
    replaced_by_id: Mapped[uuid.UUID | None] = mapped_column(
        ForeignKey("refresh_tokens.id", ondelete="SET NULL"),
        index=True,
    )

Step 06

Ask PostgreSQL, not the session

These tests check rules the database enforces: the unique hash, the foreign key, the NOT NULL columns, and the two ON DELETE rules. A constraint test proves something only when the error comes from the constraint it is about, so each one checks PostgreSQL's error class and the constraint or column it names, not just that something failed.

The delete rules run inside PostgreSQL, behind the session's back: the model has no relationship to users, so SQLAlchemy doesn't know the tokens are gone, and objects a test holds still look present. That is why the tests count rows with a query, or reload an object with refresh, instead of trusting what is in memory.

What your code has to do
  1. Add a factory that builds an unsaved, valid token for a given user, with a different random hash each time, so building several never collides by accident.
  2. Check that a new token reads back unrevoked and unreplaced, and that its expiry survives the round trip unchanged and timezone-aware.
  3. Check that a shared hash is rejected by uq_refresh_tokens_token_hash, an unknown user by fk_refresh_tokens_user_id_users, and each required column set to None by a NOT NULL error that names that column.
  4. Check that deleting a user deletes all of their tokens, counting before and after, and that deleting a replacement clears the link but keeps the older token.

def make_refresh_token(user_id: uuid.UUID, **overrides: object) -> RefreshToken:
    """Build an unsaved refresh token for a user, replacing any given fields.

    Returns:
        A new ``RefreshToken`` that has not been added to any session.
    """
    values: dict[str, Any] = {
        "user_id": user_id,
        "token_hash": secrets.token_hex(32),
        "expires_at": datetime.now(UTC) + timedelta(days=7),
    }

    values.update(overrides)

    return RefreshToken(**values)

def _count_tokens(db_session: Session, user_id: uuid.UUID) -> int:
    """Count a user's refresh tokens by asking the database.

    Returns:
        How many refresh token rows reference ``user_id``.
    """
    return db_session.execute(
        select(func.count()).select_from(RefreshToken).where(RefreshToken.user_id == user_id)
    ).scalar_one()


def test_a_new_refresh_token_is_unrevoked_and_unreplaced(user: User, db_session: Session) -> None:
    """A token saved with only the required fields is usable and unlinked."""
    token = make_refresh_token(user.id)
    db_session.add(token)
    db_session.flush()
    db_session.refresh(token)

    assert token.user_id == user.id
    assert token.revoked_at is None
    assert token.replaced_by_id is None
    assert token.created_at is not None


def test_the_expiry_reads_back_timezone_aware(user: User, db_session: Session) -> None:
    """The expiry survives a round trip unchanged and with a time zone."""
    expires_at = datetime.now(UTC) + timedelta(days=7)
    token = make_refresh_token(user.id, expires_at=expires_at)
    db_session.add(token)
    db_session.flush()
    db_session.refresh(token)

    assert token.expires_at == expires_at
    assert token.expires_at.tzinfo is not None


def test_two_refresh_tokens_cannot_share_a_hash(user: User, db_session: Session) -> None:
    """A second token with the same hash is rejected by ``uq_refresh_tokens_token_hash``."""
    token_hash = secrets.token_hex(32)
    first_token = make_refresh_token(user.id, token_hash=token_hash)
    second_token = make_refresh_token(user.id, token_hash=token_hash)

    db_session.add(first_token)
    db_session.flush()

    db_session.add(second_token)

    with pytest.raises(IntegrityError) as exc_info:
        db_session.flush()

    orig = exc_info.value.orig
    assert isinstance(orig, psycopg.errors.UniqueViolation)
    assert orig.diag.constraint_name == "uq_refresh_tokens_token_hash"


def test_a_refresh_token_must_belong_to_an_existing_user(db_session: Session) -> None:
    """A token whose user doesn't exist is rejected by its foreign key."""
    token = make_refresh_token(uuid.uuid4())
    db_session.add(token)

    with pytest.raises(IntegrityError) as exc_info:
        db_session.flush()

    orig = exc_info.value.orig
    assert isinstance(orig, psycopg.errors.ForeignKeyViolation)
    assert orig.diag.constraint_name == "fk_refresh_tokens_user_id_users"


@pytest.mark.parametrize("column", ["user_id", "token_hash", "expires_at"])
def test_required_refresh_token_columns_cannot_be_null(

    db_session: Session,
    column: str,
) -> None:
    """Saving a token with a required column set to None is rejected."""

def test_deleting_a_user_deletes_their_refresh_tokens(user: User, db_session: Session) -> None:
    """Deleting a user makes PostgreSQL delete all of their tokens."""
    user_id = user.id
    first_token = make_refresh_token(user.id)
    second_token = make_refresh_token(user.id)

    db_session.add(first_token)
    db_session.add(second_token)
    db_session.flush()

    remaining = _count_tokens(db_session, user_id)

    assert remaining == 2

    db_session.flush()

    remaining = _count_tokens(db_session, user_id)

    assert remaining == 0
