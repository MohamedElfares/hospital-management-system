Step 01

Name every setting, twice

Two files, deliberately near-identical. .env holds your real values and is ignored by Git; .env.example is committed and lists the same keys with values that are safe to publish. Anyone cloning the repository learns what to set without being handed a working secret.

The example file has one job beyond documentation: its placeholder secret should be too short to pass the rule you write in Step 03, so copying the example without generating a real key fails loudly at startup rather than running with a key the whole internet can read.

What your files have to do
  1. List the nine settings from the plan: environment, database URL, JWT secret, the two token lifetimes, the hospital timezone, allowed browser origins, log level, and demo mode.
  2. Use a database URL that names the PostgreSQL driver this project uses and points at the container from Stage 01 — on 127.0.0.1, not localhost.
  3. Generate a real secret for your own .env, and keep it out of the example: uv run python -c "import secrets; print(secrets.token_hex(32))".
  4. Give the example file a placeholder secret that is deliberately too short to be valid.
  5. Leave the origins list empty: the web app will be served from the same origin as the API, so there is nothing to allow.
  6. Confirm the real file is invisible to Git: git status should never mention it.
Hint — where each value comes from
DATABASE_URL
Driver, credentials, host, port, database. The user, password and database name are the Compose defaults from Stage 01; the prefix has to name psycopg 3 explicitly, because SQLAlchemy would otherwise pick a different driver.
secrets.token_hex(32)
32 random bytes as 64 hex characters, from the operating system's secure generator — the standard-library way to produce a signing key.
ENVIRONMENT
One of three fixed values. It drives how much detail an error response carries and whether the refresh cookie is marked Secure.
CORS_ORIGINS
Comma-separated browser origins. Empty here because the API and the web app share one origin; Step 04 is what turns the string into a list.

JWT_SECRET_KEY=change-me

REFRESH_TOKEN_EXPIRE_DAYS=7
HOSPITAL_TIMEZONE="Asia/Dubai"
CORS_ORIGINS=
LOG_LEVEL="INFO"
DEMO_MODE=False

Step 02

A typed class, not a bag of strings

Environment variables arrive as strings. The point of this class is that everywhere else in the codebase gets an int, a bool, or a value already checked against a fixed set — and that the check happens once, at import, rather than the first time a request touches it.

Two fields have no default: a URL and a secret. There is no safe value to invent for either, so the app should refuse to start without them. Everything else gets a development-friendly default from plan §15.

What your code has to do
  1. Create backend/app/core/config.py, with app/ and app/core/ each holding an __init__.py.
  2. Declare a settings class whose fields are filled from the environment and from .env, read as UTF-8.
  3. Make the database URL and the JWT secret required; give every other field the default from the plan.
  4. Type them so wrong values can't survive: the environment and log level are one of a fixed set, the two lifetimes are integers greater than zero, demo mode is a boolean.
  5. Hold the JWT secret in a type that hides itself when printed or logged, since it will end up in tracebacks and debug output otherwise.
  6. Reject unknown keys in .env, so a misspelled variable is an error rather than a setting that silently keeps its default.
Hint — the imports this step needs
BaseSettings
Base class whose fields are filled from the environment. Field names match variable names without regard to case, so database_url reads DATABASE_URL.
SettingsConfigDict
Typed options for the class: which .env file to read, its encoding, and what to do with keys that match no field.
SecretStr
A string that prints as asterisks. Its real value comes back only from get_secret_value(), which makes accidental logging hard.
Literal
Restricts a field to a fixed set of values, so an unknown environment name fails validation instead of reaching an if that quietly does the wrong thing.
Annotated, Field
Attach a constraint to a type. Annotated[int, Field(gt=0)] is an integer that must be greater than zero.
backend/app/core/config.py 
class Settings(BaseSettings):
    """Validated configuration for one running instance of the API.

    Field names match environment variable names without regard to case, so
    ``database_url`` is read from ``DATABASE_URL``. Only the database URL
    and the JWT secret are required, because no default for them is safe.
    Unknown keys in ``.env`` are rejected (``extra="forbid"``) so that a
    misspelled variable fails loudly instead of being silently ignored.
    """

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        extra="forbid",
    )

    environment: Literal["local", "test", "production"] = "local"
    database_url: str
    jwt_secret_key: SecretStr
    access_token_expire_minutes: Annotated[int, Field(gt=0)] = 15
    refresh_token_expire_days: Annotated[int, Field(gt=0)] = 7
    hospital_timezone: str = "Asia/Dubai"
    cors_origins: Annotated[list[str], NoDecode] = []
    log_level: Literal["DEBUG", "INFO", "WARNING", "ERROR"] = "INFO"
    demo_mode: bool = False

Step 03

Refuse values the app cannot use

Types alone accept plenty of nonsense: a SQLite URL is a perfectly good string, a five-character secret is a perfectly good SecretStr, and Mars/Base is a perfectly good timezone name until something tries to load it. Each of those fails much later, far from the cause.

A validator turns each into a startup error that names the variable. Three rules, each a few lines, each preventing a different kind of bad day.

What your code has to do
  1. Require the database URL to name PostgreSQL through psycopg 3. The whole design depends on PostgreSQL features, so any other dialect is a configuration mistake, not a supported option.
  2. Require the JWT secret to be at least 32 characters, because a short HS256 key can be brute-forced — and that would let someone forge tokens for any user.
  3. Require the timezone to be a name the timezone database actually knows, since business rules like "check-in only on the appointment date" depend on it.
  4. Handle both ways a timezone lookup fails: an unknown name, and a malformed one such as an empty string or a path.
  5. Keep the messages useful but safe: name the variable, quote a bad timezone, and never include the URL or the secret itself.
  6. Preserve the original error as the cause when you convert one, so the traceback still shows what really happened.
Hint — the imports this step needs
field_validator
Registers a check for one field. Raising ValueError inside it is what pydantic turns into a clean validation error naming that field — other exception types escape as crashes.
ZoneInfo
Loads a timezone by name. Constructing one is the cheapest way to ask "does this name exist?".
ZoneInfoNotFoundError
Raised for a well-formed name that doesn't exist (it is a KeyError). A malformed key raises plain ValueError instead — which is why the handler catches both.
raise ... from err
Records the original exception as the cause, so the traceback reads as a deliberate conversion rather than a second, unrelated failure.
backend/app/core/config.py 
    @field_validator("database_url")
    @classmethod
    def _check_database_url(cls, value: str) -> str:
        """Require the PostgreSQL psycopg 3 driver in the database URL."""
        if not value.startswith("postgresql+psycopg://"):
            raise ValueError("DATABASE_URL must start with postgresql+psycopg://")
        return value

    @field_validator("jwt_secret_key")
    @classmethod
    def _check_jwt_secret_key(cls, value: SecretStr) -> SecretStr:
        """Require a JWT signing secret of at least 32 characters."""
        if len(value.get_secret_value()) < 32:
            raise ValueError("JWT_SECRET_KEY must be at least 32 characters long")
        return value

    @field_validator("hospital_timezone")
    @classmethod
    def _check_hospital_timezone(cls, value: str) -> str:
        """Require a timezone name that exists in the IANA database."""
        try:
            ZoneInfo(value)
        except (ZoneInfoNotFoundError, ValueError) as err:
            raise ValueError(f"HOSPITAL_TIMEZONE {value!r} is not a valid IANA timezone") from err
        return value

Step 04

One string in, a list out

Environment variables are strings, but CORS_ORIGINS is a list. Out of the box, pydantic-settings tries to parse a list field as JSON, so a,b fails and anyone configuring the app has to write ["a","b"] in a .env file.

Comma-separated is friendlier, so the field opts out of JSON parsing and does the splitting itself — before type validation, while the value is still a string.

What your code has to do
  1. Stop the settings loader from parsing this one field as JSON, so your own code receives the raw string.
  2. Split it on commas, trim the spaces, and drop empty items — "a, b,," has to become two origins, not four.
  3. Turn an empty variable into an empty list, which is the normal case for this project.
  4. Run before type validation, since a string can't satisfy list[str] — and still accept a real list, because tests construct settings directly.
  5. Give the field a default of no origins at all.
Hint — the imports this step needs
NoDecode
Marks a field as "don't parse this for me". Attached through Annotated, it hands your validator the raw environment string instead of attempting JSON.
field_validator(mode="before")
Runs ahead of type validation. The default mode runs after, by which point a plain string has already failed to be a list.
isinstance
Lets one validator serve both callers: a string from the environment gets split, a list passed directly in a test is returned unchanged.
backend/app/core/config.py 
    @field_validator("cors_origins", mode="before")
    @classmethod
    def _split_cors_origins(cls, value: list[str] | str) -> list[str]:
        """Turn a comma-separated ``CORS_ORIGINS`` string into a list.

        Example:
            ``CORS_ORIGINS=" http://a.com , http://b.com,, "`` becomes
            ``["http://a.com", "http://b.com"]``.
        """
        if isinstance(value, str):
            return [item.strip() for item in value.split(",") if item.strip()]
        return value

Step 05

One cached entry point

The rest of the codebase needs a way to reach these values. Building the class at import time would mean every module — including tests that have no .env — pays for it just by being imported. A cached function builds it on first use instead, and hands back the same object afterwards.

While you are here, add the one derived value that security-sensitive code will ask for. Deriving it from the environment field means the two can never disagree, and nobody can flip it with a stray environment variable.

What your code has to do
  1. Expose one function that returns the settings, built the first time it is called rather than when the module is imported.
  2. Cache it, so every later call is free and every caller sees the same object.
  3. Leave a way for tests to start again after changing the environment — the cache decorator you choose should offer one.
  4. Add an is-production property derived from the environment field, for the code that decides cookie flags and error detail.
  5. Make sure that property cannot be set from the environment: it is computed, not configured.
  6. Name the function so a reader can see it is a call, not a value.
Hint — the imports this step needs
lru_cache
Caches a function's result. With no arguments it memoises the single return value, and get_settings.cache_clear() is the escape hatch tests use.
@property
A computed attribute. Callers write settings.is_production with no parentheses, and pydantic does not treat it as a field, so no environment variable can override it.
# type: ignore[call-arg]
Silences one specific false positive. Type checkers can't see that the required fields arrive from the environment, so they think the constructor is missing arguments.
backend/app/core/config.py 
    @property
    def is_production(self) -> bool:
        """Whether the app is running in production.

        This is derived from ``environment`` rather than stored separately,
        so the two can never disagree, and it is not read from an environment
        variable.
        """
        return self.environment == "production"


@lru_cache
def get_settings() -> Settings:
    """Build the settings once and return the same instance afterward.

    Settings are created on the first call instead of at import time, so
    importing a module never fails just because ``.env`` is missing. Tests
    that need different values can call ``get_settings.cache_clear()``.
    """
    return Settings()  # type: ignore[call-arg]
